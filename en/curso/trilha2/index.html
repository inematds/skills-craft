🔎 Reading Quality Signals

Install count, source, description, scope, and maintenance—the signals that distinguish a mature skill from an abandoned repo. Plus another practical checklist.

What it is:

The install count that skills.sh shows next to each skill. It's the most visible popularity signal — find-skills has 1,802,925, frontend-design 488,299.

Why learn:

High install counts correlate with quality, but they aren't proof. There's early-adopter bias and a brand effect. Knowing how to read this helps you avoid installing popular junk.

Key concepts:

power law · early-mover bias · brand effect · 0.3% have 100k+

What it is:

The owner/repo repository that hosts the skill. vercel-labs, anthropics, and microsoft carry institutional reputations; a random 3-star repo does not.

Why learn:

The source is the second-best signal after the description. Official sources keep the skill alive, follow the spec, and respond to issues.

Key concepts:

vendor-backed · anthropics/skills · vercel-labs · microsoft/azure-skills · random repo

What it is:

The frontmatter description field. A good one says WHAT the skill does AND WHEN to use it. It’s the trigger the agent reads to decide whether to activate it.

Why learn:

A clear description shows that the author understood the problem. A vague description means a skill that triggers incorrectly or never triggers. It’s the best predictor of quality.

Key concepts:

activation trigger · WHAT + WHEN · precise trigger · sub-trigger

What it is:

How much the skill tries to cover. An atomic skill solves one problem well; an “everything-about-X” skill tries to solve ten and doesn’t solve any of them properly.

Why learn:

Focused skills are absorbed into context more effectively, trigger precisely, and compose with others. A compact size (body <500 lines) is a sign of discipline.

Key concepts:

atomicity · one responsibility · composition · <500 lines

What it is:

Commit frequency, issues answered, and releases. Since skills are installed via symlink, npx skills update pulls improvements from the source automatically.

Why learn:

A living skill keeps up with changes to the framework and the spec itself. An abandoned one ages and starts giving the agent incorrect instructions.

Key concepts:

latest commit · open issues · npx skills update · symlink vs. copy

What it is:

A 7-question checklist that brings all the signals—installs, source, description, scope, maintenance, license, and fit—together in a 2-minute decision.

Why learn:

Turns intuition into a repeatable process. You stop installing based on hype and start installing based on evidence.

Key concepts:

2-minute evaluation · evidence > hype · fit with your stack · read the SKILL.md

⭐ The Best by Quality Signal

For each quality signal, the real skill that’s its perfect example—description, atomic scope, strong source, and clear discoverability, with the catalog’s actual descriptions.

What it is:

frontend-design (488k, anthropics) says what to do and when, and gives examples: "Use this skill when the user asks to build web components, pages...". supabase (99k) is "pushy" with "Triggers:...".

Why learn:

The description is the routing trigger. Seeing the perfect model gives you a pattern to copy when writing yours.

Key concepts:

what + when + examples · “pushy” · Triggers: · combating under-triggering

What it is:

vercel-react-best-practices (443k) and test-driven-development (107k, from obra/superpowers): one responsibility each, done exceptionally well.

Why learn:

Atomic scope triggers precisely and works well with other skills. It's the signal that separates a mature skill from an "everything-about-X" skill.

Key concepts:

one responsibility · sentence test without "and" · composition · process skill

What it is:

The microsoft/azure-skills suite (~358k each) and vercel-labs: official vendor, cohesive suite, actively maintained via symlink.

Why learn:

Vendor-backed is the highest level of trust—the people who build the product know the edge cases no one documents.

Key concepts:

vendor-backed · cohesive suite · npx skills update · actively maintained

What it is:

find-skills (1,802,925, vercel-labs), the most installed in the catalog: its name and purpose are instantly obvious.

Why learn:

If the name needs explaining, discovery has failed. Self-explanatory name+description become the entry point.

Key concepts:

self-explanatory name · entry point · top 100 = 43.7% · 0.3% have 100k+

What it is:

skill-creator (246k, anthropics) combines a clear description + focused scope + official source + obvious discoverability.

Why learn:

Getting several signals right doesn’t add—it multiplies. That’s why these skills lead the catalog.

Key concepts:

compound effect · meta-skill · mutual reinforcement of signals

What it is:

🛠️ How to Create a Skill That Looks (and Is) High-Quality

The hands-on part: a description that triggers correctly, atomic scope, a polish checklist, before-and-after examples of a weak skill becoming a strong one, and a ready-to-use description template.

What it is:

Write the description in three parts: the result it delivers, when to use it (concrete triggers), and a pushy stance against under-triggering.

Why learn:

It’s the routing trigger that’s always in context. Get this wrong = a skill that triggers incorrectly or never triggers.

Key concepts:

result, not activity · “Use when...” · “Triggers:” · the 100-word rule

What it is:

Keep the skill focused on a single responsibility, like vercel-react-best-practices and the azure-skills suite. Break up anything large.

Why learn:

An atomic skill is absorbed into context, triggers precisely, is testable, and composes. “Everything about X” fails at everything.

Key concepts:

single-sentence test · <500 lines · no "and"/"also" · composition

What it is:

A 7-item checklist—description, scope, <500 lines, explain why, test prompts, scripts, obvious name—before publishing.

Why learn:

Separates a skill that seems high-quality from one that is. Inspired by the canonical skill-creator workflow.

Key concepts:

checklist of 7 · polish = remove · imperative · bundled resources

What it is:

Same intent ("help with SQL"), two executions side by side: the "sql-helper and more" that nobody installs versus the postgres-best-practices pattern.

Why learn:

Show that the quality leap comes from routing and focus, not technical content.

Key concepts:

code box ✗/✓ · "and more" = infinite scope · routing and focus

What it is:

A frontmatter template that combines frontend-design and supabase patterns, with a completed example for a migrations skill.

Why learn:

Get rid of the “blank page.” You fill in the brackets and calibrate the triggers against near-misses.

Key concepts:

template · outcome verb · examples + Triggers · calibrate near-misses

What it is:

Capture intent → draft → 2-3 test prompts vs. baseline → generalize and trim → optimize the description → package.

Why learn:

Creating a good skill is iterative, not a guess. The loop ensures it actually helps before you publish it.

Key concepts:

with-skill vs baseline · should-trigger/should-not · iterate · package

🚀 Advanced Tips: Signals Only Experts See

The finer signals: triggering precision, context efficiency, reading transcripts, eval pass rate and discriminating assertions, variance, and why a popular skill can still be bad.

What it is:

The skill fires in the right cases (should-trigger) and stays quiet in similar-but-wrong ones (near-misses). A false positive is worse than not triggering.

Why learn:

It’s the invisible signal: a skill that triggers incorrectly injects irrelevant context and degrades the response.

Key concepts:

should-trigger · should-NOT-trigger · false positive/negative · precision vs. coverage

What it is:

The 3 levels of progressive disclosure: the description is always in context, the body loads when triggered, and bundled resources load on demand. A skill that uses too many tokens takes up space.

Why learn:

30 bloated descriptions cost thousands of tokens before any task begins. A dense, concise description is a budget.

Key concepts:

3 levels · cost of always-active skills · push details to level 3

What it is:

Reread real sessions looking for repetition, non-triggering (a skill that should have activated), and incorrect triggering (near-misses).

Why learn:

Transcript is the best free eval. Each pattern you find is a concrete adjustment to a skill or its description.

Key concepts:

repetition → script · no trigger → weak trigger · wrong trigger → near-miss

What it is:

A discriminating assertion fails without the skill and passes with it. The number that matters is the delta between with-skill and baseline.

Why learn:

A 100% pass rate that doesn’t distinguish the baseline from the with-skill results is false reassurance—it doesn’t measure the skill’s contribution.

Key concepts:

discriminating assertion · delta vs. baseline · always run the baseline

What it is:

The model is stochastic: the same skill passes one run and fails another. Run the eval several times and look at the mean ± standard deviation.

Why learn:

90% flaky is worse than 80% stable. Stability is quality; a single run is misleading.

Key concepts:

stochastic · mean ± σ · imperative reduces variance · explain why

What it is:

Power law: the top 100 account for 43.7% of installs; only 0.3% (131 skills) exceed 100k. There’s early-mover and brand bias.

Why learn:

A popular skill may be abandoned, built for a different stack, or bloated. Install is where you start investigating, not where you finish.

Key concepts:

early-mover bias · stack fit · maintenance · evidence > hype
