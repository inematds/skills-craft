🗺️ Por qué estudiar anatomías reales

La mejor forma de aprender a escribir un SKILL.md es analizar a fondo las que ya ganaron. Las skills más instaladas del ecosistema (frontend-design con 488.299 instalaciones, skill-creator con 246k, azure-ai con 358.744) no son casualidad: cada una resuelve el problema de una forma diferente y, juntas, forman un catálogo de patrones listos para imitar.

La regla del robo honesto

No copies el contenido: copia la forma. Cada anatomía de abajo resuelve una compensación diferente (concisión vs. cobertura, simplicidad vs. enrutamiento). Identifica cuál se parece a tu skill y usa el esqueleto correspondiente.

2

🎨 frontend-design — description breve y precisa

La skill más instalada de Anthropic (488.299 installs) también es una de las más concisas en el frontmatter. La description hace tres cosas en una sola frase: dice qué hace, lista cuándo usar con ejemplos concretos, y termina con el diferencial ("evita la estética genérica de la IA").

frontmatter real de frontend-design:

---
name: frontend-design
description: Create distinctive, production-grade
  frontend interfaces with high design quality.
  Use this skill when the user asks to build web
  components, pages, artifacts, posters, or
  applications (examples include websites, landing
  pages, dashboards, React components, HTML/CSS
  layouts, or when styling/beautifying any web UI).
  Generates creative, polished code and UI design
  that avoids generic AI aesthetics.
license: Complete terms in LICENSE.txt
---

✓ Qué copiar

  • ✓Verbo de acción al comienzo («Create...» )
  • ✓Lista de ejemplos entre paréntesis como activadores
  • ✓Frase final que diferencia el resultado
  • ✓Cero carpetas: un único cuerpo lo resuelve todo

✗ Cuándo NO imitar

  • ✗Si tu skill cubre varios dominios distintos
  • ✗Si necesita ejecutar scripts deterministas
  • ✗Si el cuerpo superaría las 500 líneas sin carpetas

💡 Consejo

Usa el molde frontend-design cuando tu skill sea «una sola competencia»: sin variantes ni scripts. Es el arquetipo más común y el más fácil de mantener.

3

🧰 skill-creator — la anatomía de varios archivos

La skill-creator de Anthropic (246k instalaciones, ~33KB) es el ejemplo canónico de skill grande organizada por carpetas. El cuerpo del SKILL.md se limita a lo esencial; el resto vive en scripts/, references/ e assets/ — exactamente los tres directorios canónicos.

La anatomía que documenta el propio skill-creator:

skill-name/
├── SKILL.md (required)
│   ├── YAML frontmatter (name, description)
│   └── Markdown instructions
└── Bundled Resources (optional)
    ├── scripts/    - código determinístico
    ├── references/ - docs sob demanda
    └── assets/     - templates, ícones, fontes

Mira cómo el cuerpo apunta para los recursos en lugar de pegar el contenido: el patrón de referencia que mantiene corto el SKILL.md:

referencias reales en el cuerpo de skill-creator:

See `references/schemas.md` for the full schema.

python -m scripts.package_skill <path/to/skill>

Read the template from `assets/eval_review.html`

Qué copiar

Los tres directorios con sus funciones exactas y la disciplina de citar cada archivo en el cuerpo con una frase que indique "cuándo leerlo". Es el esqueleto que debes imitar cuando tu skill tiene código reutilizable, documentación extensa y plantillas de salida.

🗂️ supabase — enrutamiento por dominio en la descripción

La skill supabase (99k installs) tiene una de las descriptions más agresivas del ecosistema: empieza con "Úsala para CUALQUIER tarea relacionada con Supabase" y vuelca una lista enorme de Triggers: — productos, bibliotecas, problemas de autenticación. Es puro enrutamiento: la description por sí sola ya sabe cómo dirigir al agente.

frontmatter real de supabase (fragmento):

---
name: supabase
description: "Use when doing ANY task involving
  Supabase. Triggers: Supabase products (Database,
  Auth, Edge Functions, Realtime, Storage, Vectors,
  Cron, Queues); client libraries (supabase-js,
  @supabase/ssr) in Next.js, React, SvelteKit;
  auth issues (login, sessions, JWT, RLS);
  Supabase CLI or MCP server; migrations,
  security audits, Postgres extensions."
metadata:
  author: supabase
  version: "0.1.2"
---

✓ Qué copiar

  • ✓La etiqueta Triggers: seguido de una lista por categoría
  • ✓El assert "ANY" para forzar la activación
  • ✓Bloque metadata: con author y version

✓ Y en el cuerpo

  • ✓"Principios fundamentales" numerados al inicio
  • ✓Checklists de seguridad con trampas reales
  • ✓Enlaces a la documentación oficial en vez de copiarlo todo

💡 Consejo

Cuando tu skill es el "portero" de toda una plataforma, copia el patrón de Triggers: categorizados: eso es lo que garantiza que el agente se active en cualquier punto del dominio.

☁️ microsoft-foundry y azure-ai — skills operativas grandes

Las skills de Microsoft (foundry y azure-ai, ~358–360k instalaciones, 19KB+) muestran cómo ampliar una skill operativa y enorme sin perder el control: la description usa USE FOR e DO NOT USE FOR para delimitar el alcance, y el cuerpo es una tabla de sub-skills que enruta a archivos por workflow.

description de microsoft-foundry (fragmento con límites de alcance):

description: "Deploy, evaluate, fine-tune, and
  manage Foundry agents end-to-end...
  USE FOR: deploy agent, hosted agent, create
  agent, evaluate agent, optimize prompt, deploy
  model, RBAC, quota, troubleshoot agent...
  DO NOT USE FOR: Azure Functions, App Service,
  general Azure deploy (use azure-deploy)."

cuerpo: tabla de sub-skills que enruta por workflow:

| Sub-Skill | When to Use      | Reference        |
|-----------|------------------|------------------|
| deploy    | Build, push, ACR | deploy/deploy.md |
| invoke    | Send messages    | invoke/invoke.md |
| observe   | Run evals        | observe.md       |
| quota     | Capacity, quota  | quota/quota.md   |

Qué copiar

  • •USE FOR / DO NOT USE FOR — desambigua skills cercanas y evita activaciones incorrectas.
  • •Tabla de sub-skills — el SKILL.md se convierte en un enrutador; cada workflow va en su propio archivo.
  • •Requisitos previos a la ejecución — comprobaciones previas explícitas antes de cualquier acción.
